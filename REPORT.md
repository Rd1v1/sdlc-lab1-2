# Практики 1–2. Файловый менеджер и CI/CD

## Цель

Разработать консольный файловый менеджер с безопасной обработкой файлов и журналом действий. Настроить сборку, тестирование, статический анализ и развёртывание этого же приложения через CI/CD.

## Практика 1

Приложение принимает команды через argparse. После проверки пароля файловая операция выполняется внутри рабочего каталога, а метаданные и действие сохраняются в SQLite. Основные части разделены на модули: интерфейс, файлы, аудит, пути, блокировки, ZIP и диски.

| Возможность | Проверка | Результат |
| --- | --- | --- |
| Сведения о дисках и файловой системе | Консольная демонстрация `drives` | Выполнено |
| Чтение, запись, изменение, удаление | Тесты файловых операций и демонстрация | Выполнено |
| Копирование и перемещение | Проверка содержимого и запрета перезаписи | Выполнено |
| JSON и XML | Запись/чтение, Unicode, ошибочный XML | Выполнено |
| ZIP | Создание, распаковка, пустые каталоги | Выполнено |
| Метаданные файлов и журнал | Проверка таблиц Files и Operations | Выполнено |
| Пользователи и права | Проверка хэша пароля и запрета чужого файла | Выполнено |
| Безопасность путей | Traversal, абсолютные пути, незарегистрированные файлы | Выполнено |
| Безопасность архивов | Выход за каталог, ссылки, конфликт имён, размеры и сжатие | Выполнено |
| Конкурентные операции | Полнота записи из потоков и отдельных процессов | Выполнено |
| Ошибки ввода и файловой системы | Неверная команда, каталог вместо файла, PermissionError | Выполнено |

Пароли хранятся как scrypt-хэши со случайной солью. SQL-запросы параметризованы. DTD и объявления сущностей XML запрещены. Запись выполняется через временный файл и атомарную замену; файловые операции защищены межпроцессной блокировкой.

## Практика 2

| Стадия | Действие | Результат выполнения |
| --- | --- | --- |
| build | Сборка реального приложения и сохранение build-image | Успешно локально и в GitHub Actions |
| test | Те же 21 тест внутри контейнера, JUnit XML | Успешно локально и в GitHub Actions |
| sast | Bandit, блокировка находок HIGH | Успешно локально и в GitHub Actions |
| deploy | Runtime-образ, UID 10001, `/health`, консольный smoke-тест | Успешно локально и в GitHub Actions |

Стадии связаны через needs. Образ передаётся артефактом между заданиями; кэш ускоряет подготовку зависимостей. JUnit сохраняется даже при ошибке тестов. Ненулевой код теста или SAST останавливает дальнейший конвейер. Секреты не включены в исходники.

JUnit XML — формат результата тестирования; тесты написаны на Python unittest. Контейнерный HTTP-маршрут `/health` нужен для проверки развёртывания и не открывает доступ к файловым операциям.

## Ограничения

SQLite не поддерживает хранимые процедуры; обращения к данным выполняются параметризованными запросами. Прямой доступ другого процесса к каталогу и БД находится вне модели разграничения пользователей приложения. Восстановление после аварии между изменением файла и записью аудита не реализовано.

Локальный и удалённый контейнерные конвейеры выполнены успешно. В обоих случаях проверяется тот же файловый менеджер и тот же набор тестов.

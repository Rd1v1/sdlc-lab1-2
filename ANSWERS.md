**1. Что такое JSON?**

**Короткий ответ:** JSON — текстовый формат хранения и передачи структурированных данных. Он описывает значения, объекты и массивы и не зависит от языка программирования.

JSON расшифровывается как JavaScript Object Notation. Несмотря на название, его используют Python, Java, C#, JavaScript и другие языки. JSON сам по себе не является программой или базой данных. Определение формата: [RFC 8259](https://www.rfc-editor.org/rfc/rfc8259).

Пример:

```json
{
  "name": "Филипп",
  "age": 20,
  "student": true,
  "subjects": ["Python", "Безопасность"],
  "comment": null
}
```

В JSON есть шесть видов значений: объект, массив, строка, число, логическое значение и `null`. Имена свойств объекта — строки в двойных кавычках. В стандартном JSON нет комментариев и запятой после последнего элемента. Верхним значением может быть не только объект или массив, но и, например, строка или число.

В Python объект JSON обычно становится `dict`, массив — `list`, `true`/`false` — `True`/`False`, `null` — `None`.

В LAB 1 методы `write_json` и `read_json` сохраняют и читают JSON через общий механизм файловых операций. Код: [safe_file_manager.py](lab1/src/safe_file_manager.py), методы `write_json` и `read_json`.

**2. Что такое сериализация и десериализация?**

**Короткий ответ:** сериализация превращает данные программы в представление, пригодное для хранения или передачи; десериализация читает это представление и восстанавливает данные в памяти.

Например, словарь Python можно сериализовать в JSON-строку, записать в файл, а позже прочитать и десериализовать обратно. Сериализация не обязательно бинарная. Она также не означает шифрование или сжатие. Подробнее: [OWASP — Deserialization](https://cheatsheetseries.owasp.org/cheatsheets/Deserialization_Cheat_Sheet.html).

```python
import json

data = {"name": "Филипп", "student": True}  # Данные в памяти: dict.

text = json.dumps(data, ensure_ascii=False)  # Сериализация: dict → str.
restored = json.loads(text)                 # Десериализация: str → dict.

assert restored == data
```

`ensure_ascii=False` оставляет кириллицу читаемой. `indent=2`, используемый в проекте, добавляет отступы. Суффикс `s` в `dumps`/`loads` относится к работе со строкой; `dump`/`load` работают с файловым объектом. Описание функций: [документация Python — json](https://docs.python.org/3.13/library/json.html).

В LAB 1:

```python
def write_json(self, name, value, user_id):
    self.write_text(name, json.dumps(value, ensure_ascii=False, indent=2), user_id)

def read_json(self, name, user_id):
    return json.loads(self.read_text(name, user_id))
```

При записи данные сначала превращаются в JSON-текст, затем сохраняются как UTF-8. При чтении сначала проверяются путь, владелец и размер файла, затем прочитанный текст разбирается в структуры Python.

**3. Чем опасна десериализация JSON и других форматов?**

**Короткий ответ:** опасность возникает, когда приложение доверяет внешним данным, восстанавливает из них опасные объекты или расходует слишком много ресурсов. Обычный `json.loads` без пользовательских обработчиков разбирает данные и не исполняет содержащиеся в строках команды.

Нужно различать два случая:

- **Обычный JSON:** остаются риски чрезмерного размера и вложенности, неподходящих типов и подмены значений, которым программа ошибочно доверяет. Документация Python прямо предупреждает о расходе CPU и памяти при разборе недоверенного JSON: [Python — json](https://docs.python.org/3.13/library/json.html).
- **Восстановление произвольных объектов:** например, `pickle.loads` может выполнить код при загрузке специально подготовленных данных. Поэтому чужие данные нельзя загружать через `pickle`. Это прямо указано в [документации Python — pickle](https://docs.python.org/3.13/library/pickle.html).

Пример ошибки доверия: пользователь передал JSON `{"role":"admin"}`, а приложение назначило ему права администратора. JSON-парсер мог отработать правильно; ошибка находится в логике назначения прав.

Практические меры защиты: ограничивать вход до разбора, проверять глубину и структуру, допустимые поля, типы и диапазоны значений; не использовать `eval` для JSON и не восстанавливать произвольные классы из недоверенного ввода.

В LAB 1 используется стандартный `json.loads`, а не `eval` или `pickle`. Владелец файла определяется по аутентифицированному `user_id` и БД, а не по полю внутри JSON.

Границы текущей реализации: при чтении файла действует лимит 1 МиБ. Отдельной прикладной схемы JSON и собственной проверки глубины нет. В команде `json-write` разбор `--value` происходит до проверки размера сохраняемого файла, поэтому нельзя говорить, что каждый JSON-ввод ограничен до десериализации. Код: [app.py](lab1/src/app.py), ветка `json-write`.

**4. Какие атаки бывают при обработке XML? Что означают DTD, XXE и DDE?**

**Короткий ответ:** типичные угрозы XML — внешние сущности XXE, разрастание сущностей с отказом в обслуживании и инъекции при небезопасном построении XML или XPath-запросов. DTD — механизм описания XML-документа, а не название атаки. DDE — другой механизм Windows, его не следует путать с DTD.

**DTD — Document Type Definition.** Может описывать допустимую структуру XML и объявлять сущности — именованные значения, на которые документ ссылается как `&name;`. DTD связан с объявлением `<!DOCTYPE ...>`, сущности объявляются через `<!ENTITY ...>`.

**XXE — XML External Entity.** Если парсер разрешает внешние сущности, документ может заставить его обратиться к локальному файлу или сетевому ресурсу. Последствия зависят от настроек и прав процесса: чтение доступных файлов, утечка данных или SSRF — запросы от имени приложения к другим ресурсам. Защита — отключать ненужные DTD и внешние сущности, запрещать внешние обращения. Источник: [OWASP — XML External Entity Prevention](https://cheatsheetseries.owasp.org/cheatsheets/XML_External_Entity_Prevention_Cheat_Sheet.html).

**XML-бомба, или Billion Laughs.** Вложенные сущности многократно ссылаются друг на друга. Маленький документ при раскрытии может превратиться в огромный объём текста и исчерпать память или процессорное время. Это DoS — отказ в обслуживании. Защита включает запрет сущностей и ограничения ресурсов. Безопасность также зависит от версии XML-парсера: [Python — XML security](https://docs.python.org/3.13/library/xml.html#xml-security).

**XML/XPath-инъекция.** Если непроверенный ввод склеивают с XML-разметкой, он может изменить структуру документа. Если его склеивают с XPath-выражением, он может изменить условие поиска. Защита — строить XML через API, а значения XPath передавать отдельно от фиксированного выражения через механизм привязки переменных. В LAB 1 пользовательские XPath-запросы не формируются. Подробнее: [OWASP — XPath Injection Prevention](https://cheatsheetseries.owasp.org/cheatsheets/XPath_Injection_Prevention_Cheat_Sheet.html).

**DDE — Dynamic Data Exchange.** Это механизм обмена данными между приложениями Windows. Он не является XML DTD или внешней XML-сущностью. В исходном сообщении написано «xml dde»; возможно, имелось в виду DTD или XXE, поэтому здесь разобраны все три термина. Определение DDE: [Microsoft — About Dynamic Data Exchange](https://learn.microsoft.com/en-us/windows/win32/dataxchg/about-dynamic-data-exchange).

**Атака через DDE:** злоумышленник использует DDE-связи в документе Office, чтобы побудить приложение запустить другую программу или команду. Возможность зависит от приложения, настроек безопасности и действий пользователя; например, Microsoft описывает вредоносный документ с запросом подтверждения, после которого запускается загрузчик. Защита — обновления Office, ограничения запуска DDE и отказ от разрешения внешнего содержимого в недоверенных документах. Источники: [Microsoft — DDEDownloader](https://www.microsoft.com/en-us/wdsi/threats/malware-encyclopedia-description?Name=Exploit%3AO97M%2FDDEDownloader.A), [настройки DDE в Excel](https://support.microsoft.com/en-us/excel/microsoft-excel-security-enhancements-in-the-january-2022-update-kb5010321). LAB 1 не открывает документы через Office и не использует DDE.

В LAB 1 перед разбором XML вызывается `_parse_xml`:

```python
if len(xml_text.encode("utf-8")) > self.max_file_bytes:
    raise SafeFileError("Размер XML превышает установленный лимит")

return SafeET.fromstring(
    xml_text, forbid_dtd=True, forbid_entities=True, forbid_external=True
)
```

Код: [safe_file_manager.py](lab1/src/safe_file_manager.py), метод `_parse_xml`. `SafeET` — `defusedxml.ElementTree`. `forbid_dtd` запрещает DTD, `forbid_entities` — объявления пользовательских сущностей, `forbid_external` — внешние ссылки. Это блокирует XXE и XML-бомбы с раскрытием сущностей. Нарушения политики и ошибки синтаксиса преобразуются в `SafeFileError` без включения содержимого XML в сообщение.

Проверки применяются и при записи, и при чтении XML. Размер в UTF-8 ограничен **до разбора**: по умолчанию 1 МиБ. Обычный XML, пространства имён, стандартные сущности `&amp;`, `&lt;`, `&gt;`, `&quot;`, `&apos;` и числовые ссылки разрешены. Похожий на DTD текст внутри комментариев и CDATA допустим: решение принимает XML-парсер, а не регулярное выражение. Для обработки требуется Expat 2.7.2+; старый парсер отклоняется с просьбой обновить Python. Зависимость `defusedxml` устанавливается из `requirements.txt`, включая runtime Docker. Отдельного ограничения глубины XML в приложении нет, поэтому универсальная защита от любого XML-DoS не заявляется. Настройки описаны в [документации defusedxml](https://github.com/tiran/defusedxml#defusedxml).

**5. Что такое ZIP-бомба и есть ли защита в лабораторной?**

**Короткий ответ:** ZIP-бомба — архив, обработка которого требует несоразмерно много ресурсов, например из-за огромного распакованного объёма. Она может заполнить диск или вызвать отказ в обслуживании. Да, в LAB 1 есть проверки размеров, числа записей и коэффициента сжатия.

Небольшой размер ZIP сам по себе не означает небольшой размер содержимого. Существуют также архивы с большим числом записей и вложенные архивы. Об угрозах архивов: [OWASP — File Upload](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html).

Проверки LAB 1 перед извлечением:

| Параметр | Лимит по умолчанию |
| --- | --- |
| Размер входного ZIP-файла | 1 МиБ |
| Число записей, включая каталоги | 1000 |
| Общий заявленный распакованный размер | 10 МиБ |
| Заявленный размер одного распакованного файла | 1 МиБ |
| Коэффициент сжатия каждой записи | 100:1 |

1 МиБ = 1 048 576 байт. Лимиты размеров и сжатия заданы в конструкторе `SafeFileManager`, а лимит числа записей — в `extract_zip`.

```python
total_size = sum(entry.file_size for entry in entries)
if total_size > manager.max_archive_bytes:
    raise SafeFileError("Распакованный архив превышает лимит")

ratio = entry.file_size / max(entry.compress_size, 1)
if ratio > manager.max_compression_ratio:
    raise SafeFileError("Степень сжатия превышает допустимый предел")
```

Код: [archives.py](lab1/src/archives.py), функция `extract_zip`. `file_size` — распакованный размер записи, `compress_size` — сжатый размер. Например, 500 КиБ после распаковки при 1 КиБ в архиве дают коэффициент 500:1, поэтому запись будет отклонена.

Проверки выполняются до записи извлечённых файлов. Данные копируются порциями по 64 КиБ; это уменьшает потребность в памяти, но само по себе не задаёт предел общего объёма. Проверки размеров используют метаданные ZIP, собственного счётчика реально извлечённых байтов в приложении нет. Вложенные ZIP автоматически не распаковываются.

В [test_safe_file_manager.py](lab1/tests/test_safe_file_manager.py) есть тест `test_zip_limits_reject_bomb_ratio_and_oversized_entries`: он проверяет отказ при чрезмерном сжатии и превышении размера. Этот тест прошёл при выполненной проверке проекта.

**6. Чем ZIP-бомба отличается от Zip Slip?**

**Короткий ответ:** ZIP-бомба атакует ресурсы, а Zip Slip использует путь внутри архива, чтобы записать файл за пределами каталога распаковки.

Например, запись с именем `../outside.txt` пытается выйти в родительский каталог. В LAB 1 запрещены пути с `..`, абсолютные пути, обратные слеши, двоеточия и символические ссылки в ZIP. Дополнительно проверяется конечный путь назначения и запрещена перезапись существующих файлов. Код: [archives.py](lab1/src/archives.py), `extract_zip`, и [paths.py](lab1/src/paths.py), `resolve_path`.
